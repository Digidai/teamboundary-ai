# TeamBoundary AI 0.1.0 source-release evidence

Date: 2026-08-08 (Asia/Shanghai)

Release owner: Gene Dai ([@Digidai](https://github.com/Digidai))

This record approves the reviewed source snapshot for an Apache-2.0 open-source release. It does
not approve a hosted production deployment or make a zero-risk, commercial-readiness, legal-clearance
or Cloudflare-endorsement claim.

## Scope

- Product: a security-first multi-tenant AI workspace built entirely on Cloudflare primitives.
- Supported run type: bounded chat only; no tools, browser, shell, arbitrary code, realtime socket,
  R2, Queue, Vectorize, container, or Sandbox runtime is included.
- Checked-in deployment state: no route, `workers.dev` and preview URLs disabled, invalid resource
  placeholders, closed production provisioning, static AI switch off, and dynamic D1 AI switch off.
- Public history: a new source-only root plus reviewed release-preparation commits. Unsupported
  pre-public experimental history and private Git metadata are not published.

## GitHub controls verified

- Repository visibility is public; issues are enabled; wiki, projects, and discussions are disabled.
- Private Vulnerability Reporting is enabled at the URL documented in `SECURITY.md`.
- Dependabot alerts and automated security fixes are enabled.
- Secret scanning and push protection are enabled.
- Default GitHub Actions token permissions are read-only and cannot approve pull requests.
- `main` requires current `verify`, `codeql`, and `secret-history` checks, one CODEOWNER approval,
  stale-review dismissal, last-push approval, conversation resolution, and linear history.
- Force pushes and branch deletion are disabled. Administrator enforcement is intentionally off
  while the project has one maintainer; the direct bootstrap and release-evidence pushes are
  recorded exceptions. Future changes are expected to use pull requests.

## Name and legal limits

`TeamBoundary AI` passed the dated preliminary exact-name and public-registry screen recorded in
`NAME_CLEARANCE.md`. That screen found no exact software use but is not formal trademark clearance.
Commercial brand use, registration, marketplace distribution, or material brand spending requires
qualified counsel in the intended markets and classes.

Apache-2.0 covers the repository's original source, not Cloudflare services, hosted models, model
weights, model output, or third-party data. Operators must review the corresponding service terms,
data processing, acceptable-use, export, privacy, and retention obligations.

## Explicit non-goals and residual risk

- No Cloudflare production account or customer environment was deployed or modified by this source
  release.
- The open configuration cannot deploy without an independently approved private target manifest.
- AI remains off until both reviewed static configuration and the D1 runtime gate are deliberately
  enabled. A real deployment additionally requires an existing named AI Gateway with reviewed
  input/output Guardrails and DLP; the reserved auto-created `default` Gateway is rejected.
- Hosted commercial use still requires target-account inventory, Access default-deny and exact-host
  verification, privacy/export/deletion operations, backup and restore evidence, moderation/AUP,
  incident response, cost alerts, load/abuse tests, and an independent penetration test.
- The project currently has one maintainer. Governance records this bus-factor risk rather than
  claiming redundant support.

## Release acceptance

The release owner authorized publication of this reviewed source snapshot. The v0.1.0 tag must point
to a clean commit that passes the final local and GitHub gates, and the GitHub release must attach a
source archive, normalized CycloneDX SBOM, and SHA-256 checksum manifest.
